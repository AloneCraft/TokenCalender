# 表示言語の追加手順

画面・本体の確認ダイアログ・書式（期間・枠の名前）の文言は、すべて言語ごとの辞書から出す。言語を1つ足すのに必要なのは、**辞書のファイル1つ、登録表の1行、国旗1つ**。

## 仕組み

| 場所 | 役割 |
| --- | --- |
| `src/shared/i18n/messages/ja.ts` | 元の辞書（すべての鍵を持つ）。鍵の一覧（`MessageKey`）はここから作られる |
| `src/shared/i18n/messages/<code>.ts` | 各言語の辞書。型が `Messages` なので、鍵が1つでも欠けると型検査で止まる |
| `src/shared/i18n/languages.ts` | 言語の登録表（`LANGUAGES`）、OS の言語からの選び方、翻訳（`translate`） |
| `src/renderer/i18n/flags.tsx` | 国旗の SVG（Windows は国旗の絵文字を表示できないため） |
| `src/renderer/components/LanguagePicker.tsx` | 言語の選択欄（設定画面と左の案内帯の下） |
| `tests/unit/i18n.test.ts` | 鍵の過不足・空の訳・差し込み `{name}` の食い違い・言語の選び方を確かめる |

表示言語の決め方: 設定が「OS に合わせる」なら、OS の言語の並び（優先順）から登録されている言語を探す（`ja-JP` は `ja` に一致）。無ければ英語。画面は `navigator.languages`、本体は `app.getLocale()` を使う（どちらも起動時の `--lang` を反映する）。

本体・問い合わせスレッドは、画面に出す文を返さず、記号（`cancelled`、`not_ours` など）を返す。画面側で `msg.<記号>` の鍵で訳す（`useMsg`）。

## 対応している言語

| コード | 言語名 | 国旗 | 備考 |
| --- | --- | --- | --- |
| `ja` | 日本語 | 日の丸 | 元の辞書 |
| `en` | English | 星条旗 | OS の言語に合う辞書が無いときの代わり |
| `ko` | 한국어 | 太極旗 | 最初に追加した言語。手順の実例（`messages/ko.ts`、`languages.ts` の1行、`flags.tsx` の太極旗） |
| `zh-Hans` | 简体中文 | 五星紅旗 | OS の `zh-CN`・`zh-SG`・`zh` から選ぶ（`osTags`） |
| `zh-Hant` | 繁體中文 | 青天白日満地紅旗 | OS の `zh-TW`・`zh-HK`・`zh-MO` から選ぶ。台湾の用語（設定・快取・專案） |
| `es` | Español | スペイン | 国章は省いた簡略版。複数形あり |
| `pt-BR` | Português (Brasil) | ブラジル | ポルトガル（`pt-PT`）など `pt` の全地域でこの辞書を使う（`osTags: ['pt']`） |
| `fr` | Français | フランス | 複数形は 0 も単数 |
| `de` | Deutsch | ドイツ | `de-AT`・`de-CH` も同じ辞書 |
| `ru` | Русский | ロシア | 複数形が3つの形（1・2〜4・5以上）。`.one`・`.few`・`.many`・`.other` |
| `uk` | Українська | ウクライナ | ロシア語と同じく複数形が3つの形 |

## 言語を足す手順（例: 韓国語 `ko` は、この手順で足した）

1. `src/shared/i18n/messages/ko.ts` を作る。`en.ts` を写して、値だけを訳す。

   ```ts
   import type { Messages } from '../languages.ts';
   export const ko: Messages = {
     'nav.calendar': '캘린더',
     // …すべての鍵
   };
   ```

2. `src/shared/i18n/languages.ts` の `LANGUAGES` に1行足す。言語名はその言語の文字で書く。`rangeSeparator` は範囲の区切り（日本語「〜」、中国語「～」、韓国語「~」、ほかは「–」）。

   ```ts
   { code: 'ko', nativeName: '한국어', englishName: 'Korean', locale: 'ko-KR', dir: 'ltr', rangeSeparator: '~', flag: 'kr', messages: ko },
   ```

   OS は地域つきのタグ（`zh-TW`、`pt-PT` など）を返す。コードと違う地域のタグも同じ言語にしたいときは `osTags` に前方一致のタグを足す（例: `osTags: ['zh-tw', 'zh-hk', 'zh-mo']`）。複数に当たったときは、長い（具体的な）方を選ぶ。

3. 国旗が無ければ、`FlagId` に `'kr'` を足し、`src/renderer/i18n/flags.tsx` に縦横比 3:2（30×20）の SVG を足す。
4. 確かめる。

   ```bash
   npm run typecheck && npx vitest run tests/unit/i18n.test.ts
   ```

   ```bash
   node scripts/manual-shots.ts D:/CodexTemp/TokenCalendar/manual-work-ko docs/images/ko ko
   ```

   画面写真のスクリプトは、ボタン名を言語ごとに持っているため、言語を足したら `scripts/manual-shots.ts` の表にも足す。

## 訳すときの決まり

- 左の案内帯は幅が狭い（76px）。`nav.*` の訳は短く、おおむね10文字以内にする（韓国語の「데이터 소스」は途中で折れたため「데이터」にした）。画面の通し試験が、案内帯の名前がはみ出していないかを言語ごとに確かめる。
- 図の右端に出す「上限」「目標」（`dash.chart.limit`・`dash.chart.target`）は、長いと切れる。8文字を超えるときは短くする。
- 画面に直接書かれた範囲記号（「〜」）や日本語の文を残さない。画面の通し試験が、ひらがな・カタカナと「〜」が混ざっていないことを、言語ごとに確かめる。
- `{pct}`・`{name}` などの差し込みは、名前を変えずにそのまま残す（位置は言語に合わせて動かしてよい）。試験が食い違いを見つける。
- 「公式」「計画」「推定」は、数値の根拠の違いを表す大事な言葉。言語の中で一貫した訳語を使う。
- 「API料金換算」は、請求額ではないことが伝わる訳にする。
- 数で形が変わる言語は、`<鍵>.one`・`<鍵>.other` などを足し、呼び出し側で `count` を渡す（例: `src.unreadable`）。分類は `Intl.PluralRules` の値（zero・one・two・few・many・other）。
- 製品名・モデル名（Claude、Codex、gpt-6.1-sol など）は訳さない。

## まだ対応していないこと

- **右から左に書く言語**（アラビア語・ヘブライ語など）: 登録表の `dir: 'rtl'` で文字の向きは変わるが、画面の配置（左の案内帯、表の右寄せなど）は左右反転していない。足すときは CSS の対応が必要。
- **翻訳の質**: 韓国語・中国語・スペイン語・ポルトガル語・フランス語・ドイツ語・ロシア語・ウクライナ語は AI が訳したもので、母語の方の確認は受けていない。不自然な言い回しが残っている可能性がある。
- **説明書**（`docs/index.md`、`docs/en/index.md`）は言語ごとに別のファイル。日本語と英語だけで、ほかの言語の説明書はまだ無い（アプリの画面だけ対応）。足すときは `docs/<code>/index.md` を足し、各言語の版の先頭のリンクに加える。
- **説明書の画面写真の撮影**（`scripts/manual-shots.ts`）は、ボタン名の表を日本語と英語だけ持っている。韓国語の写真を撮るときは、表に韓国語の名前を足す。
- **書き出しファイルの列名**は英語の固定の名前（機械が読むため訳さない）。
